# 🤖 RAG Chat Bot — Корпоративный AI-ассистент

Интеллектуальная система для работы с корпоративной базой знаний на основе технологии **RAG (Retrieval-Augmented Generation)**. Ассистент находит релевантную информацию в документах компании и генерирует точные ответы на вопросы сотрудников.

## ✨ Возможности

- 🔍 **Семантический поиск** по корпоративным документам (HR, IT, Legal)
- 🧠 **Генерация ответов** с помощью локальной LLM (Qwen 3.6 35B)
- 📄 **Поддержка множества форматов**: PDF, DOCX, Markdown, TXT
- 🏷️ **Автоматическое обогащение метаданных** (отдел, уровень доступа, превью)
- ⚡️ **Высокая производительность** благодаря кэшированию моделей в памяти
- 🛡️ **Защита от галлюцинаций** — модель отвечает только на основе найденных данных
- 📊 **Прозрачность** — возвращает источники и оценки релевантности

## 🏗 Архитектура

```
┌─────────────┐
│  Пользователь │
└──────┬──────┘
       │ POST /chat
       ▼
┌─────────────────┐
│  FastAPI Server │
│   (main.py)     │
└────────┬────────┘
         │
         ├─► 📚 Поиск в Qdrant (векторная БД)
         │   └─► HuggingFace Embeddings (bge-small)
         │
         └─► 🤖 Генерация ответа (LLM Agent)
             └─► Локальная модель Qwen 3.6 35B
```

### Поток данных:
1. Пользователь отправляет вопрос через API
2. Система ищет топ-5 релевантных чанков в Qdrant (score > 0.3)
3. Контекст форматируется и передается в LLM
4. Модель генерирует ответ, используя ТОЛЬКО найденные данные
5. Ответ возвращается пользователю с указанием источников

## 🚀 Быстрый старт

### 1. Клонирование репозитория

```bash
git clone https://github.com/DaVinci113/rag_use.git
cd rag_use
```

### 2. Установка зависимостей

Проект использует современный менеджер пакетов **uv** для быстрой установки:

```bash
# Установка uv (если еще не установлен)
pip install uv

# Установка зависимостей проекта
uv sync
```

### 3. Настройка окружения

Скопируйте `.env.example` в `.env` и настройте параметры:

```bash
cp .env.example .env
```

Отредактируйте `.env`:

```env
# Qdrant
QDRANT_HOST="localhost"
QDRANT_PORT=6333

# Эмбеддинги
EMBEDDING_MODEL="unsloth/bge-small-en-v1.5"
COLLECTION_NAME="corporate_docs"

# LLM (настройте под ваш сервер)
MODEL_API_KEY="your-api-key-here"
LLM_HOST="http://127.0.0.1:8888/v1/chat/completions"
OPENAI_API_KEY="not-needed"
LLM_MODEL="unsloth/Qwen3.6-35B-A3B-GGUF:UD-Q4_K_XL"
LLM_TIMELIMIT=420

SYSTEM_PROMPT="Ты — AI-ассистент для обработки клиентских обращений. Твоя задача: Собрать ответ пользователю из RAG-данных(RAG_DATA) на вопрос (Question). КРИТИЧЕСКИ ВАЖНО!!! Ничего не додумывай!!! Если нет данных, то так и сообщай"
```

### 4. Запуск Qdrant

```bash
docker-compose up -d
```

Qdrant будет доступен на `http://localhost:6333`

### 5. Индексация документов

Загрузите корпоративные документы в базу знаний:

```bash
uv run python -m scripts.ingest
```

Этот скрипт:
- Загружает все документы из `data/raw/`
- Разбивает их на чанки (1000 символов, overlap 200)
- Обогащает метаданными (отдел, уровень доступа)
- Индексирует в Qdrant

### 6. Запуск API сервера

```bash
uv run uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

Сервер будет доступен на `http://localhost:8000`

Документация API (Swagger UI): `http://localhost:8000/docs`

## 📡 Использование API

### Эндпоинт `/chat`

Отправьте POST-запрос с вопросом:

```bash
curl -X POST "http://localhost:8000/chat" \
  -H "Content-Type: application/json" \
  -d '{
    "question": "Как оформить отпуск?"
  }'
```

### Пример ответа

```json
{
  "message": {
    "choices": [
      {
        "message": {
          "content": "Согласно Политике отпусков, для оформления отпуска необходимо:\n1. Подать заявление через Vektor HR Portal не позднее чем за 14 календарных дней до планируемой даты начала отпуска.\n2. Получить согласование непосредственного руководителя (в течение 2 рабочих дней).\n3. При отпуске свыше 14 дней — согласование руководителя подразделения (в течение 3 рабочих дней).\n4. Финальная проверка и расчет Отделом кадров."
        }
      }
    ]
  }
}
```

### Настройка локальной LLM

Для работы с локальной моделью Qwen 3.6 35B рекомендуется использовать один из серверов:

- **LM Studio** (простой GUI)
- **Ollama** (CLI, легковесный)
- **vLLM** (production-ready, высокая производительность)
- **llama.cpp server** (оптимизирован для CPU)

Пример запуска через Ollama:
```bash
ollama run qwen2.5:35b
```

## 📊 Производительность

- **Первый запрос**: ~2-5 сек (загрузка модели эмбеддингов)
- **Последующие запросы**: ~200-500 мс (модель в памяти)
- **Генерация ответа LLM**: ~10-60 сек (зависит от длины контекста и железа)

### Оптимизации

✅ Модели эмбеддингов загружаются один раз при старте сервера  
✅ Qdrant клиент переиспользуется между запросами  
✅ aiohttp сессия кэшируется в `app.state`  
✅ Динамическое определение размерности вектора (защита от ошибок при смене модели)
